Proposed minimal state set for v1 classifier

Based on the full graph above, here's the smallest classifier output set that lets the wrapper route correctly. LLM+screenshot classification returns one of these strings; the wrapper switches on it.

Classifier outputVisual fingerprint (what the LLM sees in the screenshot)Dispatch action
at_signup_or_login App URL with a prominent "Continue with Google" / "Sign in with Google" button. Could be /signup or /login (both look similar) → signup_agent.py (runs OAuth click-through; works for both signup and signin since UI is identical)
in_google_oauth URL contains accounts.google.com; page shows account chooser, consent, or password prompt → signup_agent.py continues (the OAuth flow spans multiple Google pages; signup-agent handles all of them internally)
in_onboarding App URL with a modal (role="dialog") covering most of the page; modal text mentions "Welcome", "personalize", "Step N of M", or has a "Get Started" / "Finish" button → onboarding_doer_agent.py
at_dashboard_masked_key App dashboard (no modal); visible "API Key" heading; key shown as *********** or ••••••• → get_api_agent.py
at_dashboard_with_visible_key App dashboard; key shown as plain text matching hb_[a-z0-9]+ → extract directly via state-read; no sub-agent needed
blocked_external_gate Any of: captcha, paywall, account-locked banner, email-verification required, 2FA challenge, payment form → declare disposition blocked; abort with the specific gate in summary
unknown None of the above match — page doesn't resemble any expected state → declare disposition failed; abort with screenshot attachment for diagnosis

Why exactly seven states (not more, not fewer)

  • One per sub-agent — each of our three existing sub-agents (signup, onboarding-doer, get-api) needs its own dispatch trigger.
  • Plus "Google OAuth in flight" — distinct from "at_signup_or_login" because signup-agent's ReAct loop spans multiple Google pages; we want the classifier to recognize "still in OAuth" and NOT re-dispatch signup-agent (which already owns it).
  • Plus "visible key" — if the key is already in DOM (e.g., after a prior reveal that we didn't clean up), we don't even need get-api-agent; direct extraction is free.
  • Plus "blocked external gate" — clean abort path for captcha/paywall/etc. that can't be auto-resolved.
  • Plus "unknown" — escape hatch for unanticipated states; logs the screenshot for offline diagnosis.

Cost & latency estimate

LLM+screenshot classifier vs regex-based, per outer-loop iteration.

ApproachCost/classificationLatency/classificationOuter-loop overhead total (4-7 iterations typical)Tradeoff
LLM+screenshot (chosen) ~$0.02 (vision-capable model, single screenshot input) ~3-5s per call +~$0.10-0.15 + 15-30s on top of sub-agent costs Robust to UI changes; no regex maintenance per-site
Regex on opencli state (alternative) $0 <100ms +$0 + ~1s Cheaper but brittle to DOM restructures; per-site regex maintenance

For a single tool the difference is small. For 5+ tools the cumulative regex-maintenance burden tips toward LLM. Tradeoff favors LLM at scale — confirmed by the user's choice.

Decision checkpoints before implementation

  1. Lock the 7-state set — does the proposed set cover everything you want classified? Anything to add (e.g., explicit "at_settings_subpage" for tools whose key lives on a sub-route)? Drop (e.g., merge at_signup_or_login + in_google_oauth since same sub-agent handles both)?
  2. Pick the vision model — Claude (via claude -p with image input) vs OpenAI vision vs Gemini. Claude-via-claude-p keeps us on a single LLM provider and reuses existing auth.
  3. Screenshot capture mechanism — opencli browser <sess> screenshot <path> already works; just call it before each LLM classification.
  4. Classifier prompt design — single-call returning JSON {state, confidence, evidence}. Evidence string for the trace.
  5. Outer-loop max iterations — propose 10 (vs the 15 inside each sub-agent's inner loop). Hard cap to prevent runaway.
  6. State-loop guard — if classifier returns same state 3 outer iterations in a row, abort. Belt-and-braces over each sub-agent's own internal loop detection.

Once 1-6 are locked, the implementation is ~120 lines refactor of hyperbrowser_signup.py. The 3 sub-agent scripts stay untouched — only the wrapper changes.
