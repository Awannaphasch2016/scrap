UI rendering styles for browser agents concept map · recognition heuristic · tool portfolio

A DOM-driven browser agent (opencli + LLM action picker over indexed interactives) works on some sites and not others. The dividing line isn't "is it a webapp?" or "does it have OAuth?" — it's whether the site exposes its interactive elements to Chrome's accessibility tree in a way the indexer can pick up. This page maps the ten rendering styles we encounter in practice, shows how concepts interact to determine chassis viability, and gives a 30-second recognition heuristic to classify any new tool before committing to a wrapper. The agent loop (green, center) consumes whatever artifacts are available. Which artifacts are available decides which terminal dispatch path (yellow, bottom) the loop can take. The dividing line between "chassis works" and "needs vision-coordinates" lives in whether the rendering primitive populates the accessibility tree.

What the edges say

  • SSR HTML and React+a11y both reach the accessibility tree — they're functionally equivalent from the chassis's point of view. The accessibility tree is the substrate, not "client vs server."
  • React+styled-divs reaches DOM but NOT accessibility tree — the elements exist as nodes; they're just not annotated as interactive. HID (hidden interactives) is the failure mode: visible to the user's eye, invisible to the indexer.
  • Canvas reaches only the pixel buffer — there is no DOM hierarchy to traverse. The only path forward is vision-based.
  • Iframes produce an iframe tree — opencli sees them but each frame is its own document. Per-frame eval is the workaround.
  • Hung Suspense produces nothing usable — the loading shell renders but the content fetch never resolves. Same symptom as Canvas but a different root cause.
  • Anti-bot produces ONLY the pixel buffer — and even the pixels typically show "verify you're human" instead of the real page. Vision-coordinate still doesn't help if the real content isn't loaded.
  • Electron is the same DOM rules — Electron is Chromium under the hood. If the desktop app exposes a remote-debugging port, the chassis works exactly as it does on the web.

4 Hung Suspense / infinite loading Page shell renders, main content blocked on a fetch that never resolves; progressbar visible Partial DOM (shell only); accessibility tree never populated NO — interactive: 0 with role=progressbar aria-valuenow=16 visible Hard refresh; longer wait; OR skip the route entirely and find a side-route. 5 Canvas / WebGL Content drawn as pixels via <canvas> + 2D / WebGL context; zero DOM hierarchy for the canvas content Pixel buffer only; DOM has just the canvas element itself NO — only the canvas wrapper is in DOM Vision + pixel-coordinates. Sometimes works, sometimes brittle. YouTube player, some enterprise admin tools using LitElement / Stencil
7 Cross-origin iframes Critical content embedded as third-party iframes — separate documents, separate origin policies Iframe tree (opaque from parent); each frame has its own DOM PARTIAL — sees <iframe /> as opaque element opencli browser frames to enumerate, opencli browser eval --frame N to act on each. Multi-step. Stripe checkout widget, Auth0 login widget, reCAPTCHA, hCaptcha challenges
8 Virtualized lists Only visible rows are in DOM; off-screen rows are recycled / not rendered (react-window, react-virtuoso, tanstack-virtual) DOM contains only visible portion + a sentinel for scroll position PARTIAL — N visible rows are indexed; everything else is invisible Scroll to bring target into viewport, then chassis dispatch. Multiple passes if you don't know where the target sits. Long admin tables, infinite-scroll feeds, Notion database views
9 Anti-bot fingerprinted Automated browsers detected and gated by Cloudflare Turnstile / DataDome / PerimeterX / Akamai BotManager Pixel buffer shows captcha or blank; real page never reached NO — adversarial; chassis sees the gate, not the content Stealth Chrome flags + residential proxies + human-in-loop, OR avoid the tool. Different problem class. Upwork, parts of Reddit, many e-commerce sites, ticketing sites

Otherwise identical. Cursor desktop, Slack desktop, Linear desktop, VS Code, most Electron apps

The recon command pattern

Wrap this as scripts/chassis_recon.sh when the second tool surfaces (open follow-up from the journal entry):

opencli browser recon-sess --window background tab new "$URL"
sleep 5
opencli browser recon-sess --window background state | head -50

#   interactive: N > 5  → style 1/2  → chassis works → build wrapper

#   screenshot content + state empty → style 3 (poor a11y) or 4 (Suspense)
#   screenshot blank + state empty   → style 9 (anti-bot) or auth issue

The deeper point · architecture has structural limits, not preferences

Each agent architecture maps onto a subset of the ten styles. None covers all ten. Picking an architecture is picking which styles you can drive — and that should be informed by the portfolio of tools you actually want to automate, not by what's convenient for the first one.

ArchitectureCovers stylesCost per stepWhen it's the right fit
DOM-indexer + LLM action picker (current chassis) #1, #2, partly #6-#8, #10 Cheap — ~3-5s/step + LLM Portfolio is mostly modern dev-tool SaaS with semantic markup
Vision + pixel-coordinate + LLM #3, #4, #5 (text-extracted via OCR) Medium — vision tokens per step + coord-reasoning latency Portfolio includes design tools, canvas apps, poor-a11y dashboards
Vision + DOM hybrid Everything except #9 Expensive — both substrates per step One-off high-value targets where reliability matters more than per-step cost
Managed browser provider (Browserbase, Hyperbrowser sessions, Steel.dev) #2, #3, partly #5, recording included Per-session $ (~$0.10-0.50/run) You want session recording + provider-side DOM extraction without building it
Playwright bridge #1-#3, #6-#8 cleanly Cheap, with trace recording Need rich selectors (text-content, XPath, role-with-name) + the gold-standard Trace Viewer for debugging
Stealth-browser + residential proxy #9 $ per proxy minute + setup complexity You must automate an anti-bot-protected target and have authorization
