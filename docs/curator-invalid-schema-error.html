/curator load error · Invalid schema: curator

The browser at https://personal-website-five-topaz-79.vercel.app/curator renders the page shell fine, but the first Supabase query fails with PGRST106 · Invalid schema: curator. The page surfaces this as load error: Invalid schema: curator in place of the items list. The root cause sits at exactly one step of the request flow — at the PostgREST front door, after the API key has been accepted, when it tries to route the request into the curator schema.

Literal error · returned by PostgREST to supabase-js: 
{
  "code":    "PGRST106",
  "message": "Invalid schema: curator",
  "hint":    null,
  "details": null
}
// PostgREST adds the actual cause in a sibling response when probed:
//   "Only the following schemas are exposed: public, personal_website"

Step 6 is where it fails — the rectangle in red. Every step before that succeeds; the API key is valid, the URL is correct, the JS bundle is fresh. The bad step is a project-level configuration miss in Supabase, not a code, secret, or network issue.

Why the schema is registered in Postgres but invisible to PostgREST · Supabase's REST/Realtime layer only routes requests to schemas listed in the project's Exposed schemas setting (in dashboard Settings → API → Exposed schemas). The default is public only. The personal_website schema was added when the /review page was wired. The curator schema we created in Stage A of the Supabase migration exists in Postgres (we can see it via psycopg2), but PostgREST refuses to route requests into it until it's added to the exposed list. RLS policies, indexes, and Realtime publication membership are all already correct — they just don't get exercised because PostgREST short-circuits at step 6.

Resolution

One config change, no code change, no redeploy.

  1. Open Project Settings → API.
  2. In the Exposed schemas field, change
    public, personal_website
    to
    public, personal_website, curator.
  3. Click Save. PostgREST reloads its config in ~5–10 seconds.
  4. Hard-reload /curator in the browser (Ctrl + Shift + R) to bypass any cached failure state.
Programmatic alternative (if you ever lose dashboard access or want IaC-managed exposure): 
-- via psycopg2 with SUPABASE_DATABASE_URL
ALTER ROLE authenticator SET pgrst.db_schemas TO 'public, personal_website, curator';
NOTIFY pgrst, 'reload config';
Works in self-hosted PostgREST and most Supabase setups, but the dashboard's config service may overwrite role-level settings on next project save. Treat as a quick fix, not a durable IaC path.
