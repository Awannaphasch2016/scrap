L1 — Context system as black-box

Who/what touches the tracker. v1 is operator-triggered (manual doppler run); the daily Lambda trigger is deferred to v1.5. The prospect's only interaction is reading the Google Sheet — they never see the pipeline directly.

L2 — Container deployable units inside the boundary

Inside the tracker boundary: one Python orchestrator drives one headless Playwright browser, persists to Supabase Postgres, pushes to Sheets. No queue, no Step Function — single process for v1.

L3 — Component inside realestate.run_daily

Five modules + the orchestrator entry. diff.engine is the load-bearing piece: it owns the fingerprint comparison (early-exit gate) and the field-level diff (event emission). Withdrawal detection is a separate pass because absence is set-difference, not hash.

L4 — Class dataclasses + service classes

Snapshots, probe results, and events are dataclasses (immutable per-run values, yellow). The two service classes (teal) — RealestateStore and SheetsSyncer — encapsulate I/O. The compute_fingerprint method lives on CardSnapshot so callers can't forget to compute it before upsert.

ER — Supabase schema data model · realestate.*

Three tables. re_property is the mutable current-state row (one per canonical address URL); re_event is the append-only audit log; re_watch is the operator-curated suburb list. Schema rule: persist only fields the daily diff or the Sheets sync actually needs; everything else derives from raw_card on demand. The fingerprint column on re_property is what enables the daily hash-compare early-exit.

Semantics that the diagram can't carry: current_status ∈ {ACTIVE, SUSPECT_WITHDRAWN, SOLD, WITHDRAWN}; event_type ∈ {NEW, PRICE_CHANGED, SOLD, WITHDRAWN, RELISTED}; fingerprint = sha256(canonical_url, price_text, agent_name, status_badge) — volatile fields (days_listed, inspection times, photo URLs) are deliberately excluded so day-over-day matches stay high; consecutive_misses is the 2-day grace counter that gates the canonical-page probe.

Sequence — one daily run time-ordered flow

End-to-end trace of a single run_daily invocation. Three discrete stages: (1) scrape every watched suburb, (2) diff snapshots against stored state and emit events, (3) for properties that didn't appear today and have exceeded the 2-day grace, probe the canonical page to discriminate SOLD vs WITHDRAWN. Final stage syncs to the Sheet. 

sequenceDiagram
    autonumber
    actor Op as Operator
    participant Run as run_daily.main
    participant L as fetchers.listings
    participant PW as Playwright
    participant REA as realestate.com.au
    participant D as diff.engine
    participant S as RealestateStore
    participant P as fetchers.property_page
    participant SH as SheetsSyncer
    participant GS as Google Sheets

    Op->>Run: doppler run -- python -m realestate.run_daily
    Run->>S: select from re_watch where enabled
    S-->>Run: [(sydney-cbd, nsw), (bondi, nsw), (millers-point, nsw)]

    loop For each watched suburb
        Run->>L: scrape_suburb(suburb, state)
        L->>PW: page.goto suburb /buy/in-X/list-N
        PW->>REA: HTTPS GET
        REA-->>PW: HTML (Argonaut-rendered)
        PW-->>L: page.evaluate(EXTRACT_JS)
        L-->>Run: List of CardSnapshot
    end

    Run->>D: apply_snapshot(snapshots, store)
    loop For each CardSnapshot
        D->>S: select by canonical_url
        alt not found
            D->>S: upsert_property(snap)
            D->>S: insert_event(NEW)
        else fingerprint matches
            D->>S: mark_seen(id)
        else fingerprint differs
            D->>D: field-level diff
            alt price changed
                D->>S: insert_event(PRICE_CHANGED, old/new)
            end
            D->>S: upsert_property(snap)
            D->>S: mark_seen(id)
        end
    end

    Run->>D: withdrawal_pass(store, today)
    D->>S: select where last_seen_at less than today AND status=ACTIVE
    S-->>D: list of "missed today" properties
    loop For each missed property
        D->>S: mark_miss(id) returns new miss count
        alt misses at or above WITHDRAWN_GRACE_DAYS (2)
            D->>P: probe_canonical(canonical_url)
            P->>PW: page.goto canonical /property/(addr-slug)/
            PW->>REA: HTTPS GET
            REA-->>PW: HTML with Property history block
            PW-->>P: parse recent Sold rows
            P-->>D: ProbeResult(outcome, sold_price, sold_date)
            alt outcome == SOLD
                D->>S: insert_event(SOLD, sold_price + sold_date)
                D->>S: update current_status = SOLD
            else
                D->>S: insert_event(WITHDRAWN)
                D->>S: update current_status = WITHDRAWN
            end
        end
    end

    Run->>SH: sync(store)
    SH->>S: select_active + recent events
    S-->>SH: rows + events
    SH->>GS: values.batchUpdate Properties tab
    GS-->>SH: 200 OK
    SH->>GS: values.append Events tab
    GS-->>SH: 200 OK
    SH-->>Run: SyncReport(props=N, events=M, duration_ms=T)

    Run-->>Op: [run_daily] done · n_new=X · n_price=Y · n_sold=Z · n_withdrawn=W
